V5 “Synthesis” landing — what's strong, what's weak

Full critique against the anchored context: global taste-laws + Arnel's rejections, the project DESIGN.md, and the learned taste-rulebook (rounds 1–3 locks). Objective axes scored by the impeccable 3.1.0 detector; judgment axes scored against the locks & references. No code was changed — the critique lane does not close the loop.

3.6/ 5 overall

Strongest synthesis of the set — it's the only direction that fuses the compounding proof-card, the “measured / numbers” instrument panel, and a real editorial voice, and it clears the deepest AI tells (it's media-rich, not an all-DOM page; no gradient text, no nested cards, no side-stripe accents; the no-mono lock holds). It loses points on accessibility (26 contrast hits + sub-12px micro-text), three brand-lock misses (real wordmark SVG, an orange glow on dark, numbered markers), and small voice slips (em-dash overuse, one buzzword). All fixable without touching the concept.

Prioritized punch-list

P0 · LOCK

Wordmark is a CSS mark, not the real loudface.svg

grep: 0 refs
Round-2 lock is explicit: “Always use the REAL loudface wordmark SVG (public/images/loudface.svg, indigo #4F46E5; white variant loudface-inversed.svg on dark). Never a placeholder CSS mark.” v5's nav uses class="logo" with zero references to the SVG.
grep -c "loudface.svg|loudface-inversed" → 0 nav markup: <… class="logo"> (CSS/text mark)
Fix → swap to the real SVG (indigo on light, inversed on dark). One-line change; lock compliance.
P0 · BAN

Orange glow on the dark page

detector: dark-glow
Taste-law hard ban: “No glow / halo / pulsing ring … no dark-mode glowing accents.” Two box-shadows cast an orange rgb(234,88,12) glow on a dark surface.
[dark-glow] Colored glow (rgb(234,88,12)) on dark page box-shadow w/ orange rgba on dark → 2 occurrences
Fix → remove the colored box-shadow; carry emphasis with a hairline ring + the block fill, not a glow.
P1 · A11Y

26 low-contrast hits — the weakest axis

detector: low-contrast ×26
Two are clearly real and should be fixed; a cluster of white-on-near-white reads are likely static-analysis false positives (white text that actually sits on indigo/orange color-blocks, which the file-only detector can't resolve) — verify visually before touching those.
REAL 1.8:1 #3a4441 on #0f1413 (muted text, dark section — too dim) REAL 3.6:1 #ea580c on #ffffff (orange accent on white < AA 4.5) CHECK 1.0–1.1:1 #ffffff on #fcfcfb/#f5f4f0 (likely white-on-color-block; verify)
Fix → lift dark-section muted text to ≥ #9aa6a2; darken the orange accent to ~#c2410c for small text (keep bright orange only for large display); confirm the color-block words really sit on their fill.
P1 · A11Y

Micro-text below 12px + tight leading + all-caps sentences

detector: tiny-text ×8 · tight-leading ×4 · all-caps-body ×4
The instrument-label / coordinate slot drops to 10.5–11px and runs uppercase across 33–35-char strings — both hurt legibility. Four blocks sit under 1.3× leading.
[tiny-text] 11px body · 10.5px body [all-caps-body] uppercase on 35 / 34 / 33 chars [tight-leading] line-height 1.18x / 1.26x (need ≥1.3)
Fix → floor micro-labels at 12px; reserve uppercase for ≤ ~20-char labels (sentence-case the long ones); raise body leading to ≥1.4.
P1 · TELL

Numbered section / module markers

detector: numbered-section-markers (advisory)
Taste-law standing veto: numbered markers (01/02/03) must not be laundered as “design-system sanctioned.” Detector found the full sequence. MODULE 01 / MODULE 02 on the Build/Grow cards is the clear hit. The R-01…R-05 / T-01…T-04 blueprint coordinates are borderline-defensible as the deliberate instrument motif — but the human outranks the motif, so thin them.
[numbered-section-markers] Sequence: 01, 02, 03, 04, 05, 06 grep: "MODULE 01", "MODULE 02" · R-01…R-05 · T-01…T-04
Fix → drop “MODULE 01/02” (use the verbs Build / Grow alone); keep at most one coordinate readout as signature, not a numbered index on every panel.
P1 · VOICE

Em-dash overuse (13) + one “best-in-class” buzzword

detector: em-dash-overuse · marketing-buzzword
13 em-dashes in body copy is the AI cadence tell; “best-in-class” (Dimer case line) is a flagged buzzword. The manifesto voice is otherwise distinctive and on-brand — these are surgical edits.
[em-dash-overuse] 13 em-dashes in body …its traffic — two precise… · …for growth — momentum… · …since 2020 — startups… [marketing-buzzword] “best-in-class site for a healthcare startup”
Fix → convert ~half the em-dashes to periods/commas; replace “best-in-class” with a concrete claim.
P2 · POLISH

Cramped padding & clipped overflow

detector: cramped-padding ×10 · clipped-overflow ×13
Several panels (incl. the testimonial quote and the finalcta) have children flush against a border/fill with no inset. 13 clip-containers (crop-mark frames, floating chips) risk cutting positioned children. Mostly cosmetic for a mockup; worth resolving when it becomes real components.
[cramped-padding] "quote": children flush against border+bg (no inset) [cramped-padding] "finalcta": children flush against bg on all sides [clipped-overflow] section.hero / hero-film / gauge.feature clip a positioned child
Fix → add 12–16px inner padding inside bordered/filled panels; let crop-frame corners overflow visible.
P2 · POLISH

Untinted pure #000 / #fff · width-transition · footer heading skip

detector: layout-transition · skipped-heading
Taste-law: tint every neutral (OKLCH) — found 5× pure #000, 20× pure #fff. The gauge meter animates width (reflow) vs the transform/opacity law. Footer jumps h2 → h4 (“Services”), skipping h3.
[layout-transition] transition: width [skipped-heading] <h2>…holding your site back</h2> → <h4>Services</h4> pure #000: 5 · pure #fff: 20
Fix → tint neutrals slightly; animate the gauge with transform/scaleX; demote footer column labels to non-heading or fix the level.
